# 分支协作

`pi0.5` 是本项目 π0.5 代码的集成分支，涵盖核心模型、LIBERO 五组实验及 Kinova 离线微调。OpenVLA 由队友在其独立分支维护。本次发布只创建和更新 `pi0.5`。

## 日常流程

```bash
git clone --branch pi0.5 https://github.com/pytenter/cl-VLA.git
cd cl-VLA
git switch -c feature/pi05-your-change
```

完成修改并验证后，推送自己的功能分支，在 GitHub 创建 **base = `pi0.5`** 的 PR。已有本地仓库时，先获取远端更新并确认当前基线，避免从另一模型分支误开功能分支。

PR 应说明具体问题、改变后的行为、验证命令及结果。涉及模型、冻结边界、回放、归一化、动作定义、数据划分或评估规则时，记录影响到的实验，并明确旧结果是否仍适用。CPU 小型检查、完整模型验证和正式训练结果应分别标注。

## 共享数据协议

跨模型共享的是明确的数据协议和评估约定：字段名、相机语义、状态/动作顺序与单位、动作参考系、episode 边界、数据划分、训练集统计和固定评估样本。变更先通过 PR 给出前后 schema 与兼容方式，再由各模型分支协调适配；不以整分支合并替代协议讨论。

LIBERO 的两视角/state8/action7/horizon10 与当前 Kinova 的腕部视角/state28/action7/horizon50 是两套具体协议，不应直接混用。第五组 LIBERO 的固定原型记忆来源也应保留，重新选择记忆需要另立实验记录。

## 文件与结果

数据、权重、checkpoint、回放 NPZ、视频、缓存、个人 `.env` 和凭据不进入 Git。数据与模型通过独立存储共享，仓库保留版本、来源和校验信息。提交前检查 `git diff --cached`，确认没有个人地址或大文件。

保留既有实验结果；新实验写入独立目录，记录代码提交、配置、数据/权重版本、种子和实际验证范围。不要覆盖已有运行目录，也不要把失败探针的更新次数计入有效训练轨迹。
